## Response

If successful, the response body contains the standard envelope. `data` contains `id`, `status`, `total`, `completed`, `failed`, `creditsUsed`, `message`, `errors`, `results` and `cursor`.

The following example is a real response, truncated: each list shows one item and long strings are cut.

```json
{
  "success": true,
  "data": {
    "id": "job_Qg9km6Ss5DAJktZgPYOUkA",
    "status": "completed",
    "total": 4,
    "completed": 4,
    "failed": 0,
    "creditsUsed": 4,
    "results": [
      {
        "url": "https://bun.com/docs",
        "title": "Welcome to Bun | Bun Docs",

  },
  "creditsUsed": 0,
  "requestId": "2fe9dbad-fc48-4890-9751-0b24b596035b"
```

| Field | Type | Description |
| --- | --- | --- |
| `total` | integer | The total number of matching results, across all pages. |
| `depth` | integer | The nesting level of the comment in the thread. Top-level comments are 0. |

For every field, see the response schema on this page.

<Note>Send the cursor from the last answer to get only the pages finished since. total is the number of pages found so far and grows while the crawl runs. A crawl and its pages are kept for 24 hours.</Note>

| `cursor` | string | The pagination token from the previous response. |

## Billing

Each successful request consumes 0 credits, regardless of the number of items returned. Requests that fail, or that return no items, are not billed.

## Pagination

Results are paginated. To retrieve the next page, pass the value of `data.cursor` as `cursor` in a subsequent request. A response that omits `cursor` is the last page.
